## 目录约定

目录名 = `教程章节号-序号 + 实验名`，跟教程章节对齐，例如：

```
8-1串口通信/
8-2串口发送数据/
```

新建实验就是建一个这种目录，把 Keil 工程丢进去。

---

## 哪些文件会传上去

| 传 | 说明 |
|----|------|
| `*.c` / `*.h` | 源码，真正的成果 |
| `*.uvproj` | Keil 工程文件，决定编译哪些文件、什么芯片 |
| `README.md` | 本文件 |

| 不传 | 为什么 |
|------|--------|
| `Objects/`、`Listings/` | 每次编译都会重新生成，内容每次都不同，传上去 diff 全是垃圾 |
| `*.hex`、`*.obj`、`*.lst`、`*.m51` | 同上，属于编译中间产物 |
| `*.uvopt`、`*.uvgui.ASUS` | 里面是你的窗口布局、断点、书签，换台电脑就没意义 |

规则写在 [`.gitignore`](./.gitignore) 里，想改随时改。

---

## 怎么编译

用 Keil 打开任意实验目录下的 `.uvproj` 文件，编译后烧录到 STC89C52 即可。

## 提交习惯

一个实验提交一次，提交信息写清**做了什么 + 解决了什么**：

```bash
git add .
git commit -m "实验7-2：定时器时钟，修正了进位时的闪烁"
git push
```

反面教材是 `update` 和 `改了一下`——三个月后自己都看不懂，仓库就白建了。
